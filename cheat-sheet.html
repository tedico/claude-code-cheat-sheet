Claude Code Commands Cheat Sheet

Every command from our videos, in plain English.

Each one was run on our own setup and checked against the Anthropic docs. What you'll see is what we saw.

Words on this page: Context window is everything Claude can see in a session at once. CLAUDE.md is a plain-text file of instructions Claude reads at the start of every session. Skills are saved instructions Claude uses for specific jobs. MCP servers are connectors that plug Claude into outside tools. Effort is how hard the model thinks before it answers.

/doctor prompt-audit

WHAT IT DOES
It checks your CLAUDE.md, AGENTS.md, skills, rules, and other files under .claude/ for outdated or conflicting instructions.
WHEN TO RUN IT
Run it after you retire a plan, rename a folder, or add a skill, because your files may still say what used to be true.
HOW TO RUN IT
Check your version with claude --version, then run claude update if needed, because the audit requires v2.1.283 or later. Then type /doctor prompt-audit, or add a path like /doctor prompt-audit .claude/skills/deploy to check only the part you changed.
WHAT YOU'LL SEE
You'll get a report with proposed edits, and nothing changes until you approve it. Our Sep 25 run took 6m 50s across 25 skills and found 19 issues.

/context

WHAT IT DOES
It shows what's filling Claude's context window as a colored grid by category. The categories include CLAUDE.md and memory files, skill descriptions, and MCP tools and server instructions. By default, only skill descriptions and MCP tool names load, not everything.
WHEN TO RUN IT
Run it when a session feels sluggish, before a long task, and after adding a skill or MCP server, because each one adds to what loads before you type a word.
HOW TO RUN IT
Type /context. In fullscreen, type /context all, because fullscreen collapses the per-item list.
WHAT YOU'LL SEE
You'll see the grid plus suggestions about context-heavy tools, memory bloat, and capacity. It deletes nothing, so you decide whether to /compact, /clear, or edit your files with /memory.

/model

WHAT IT DOES
It opens a picker to switch Claude's model and, if the model supports it, its effort. You choose whether the switch is your new default or for this session only.
WHEN TO RUN IT
Run it when a task is lighter or harder than usual. You can run it while Claude is still responding: once you confirm, the switch takes effect without waiting for the response to finish.
HOW TO RUN IT
Type /model. Arrow to a model, then use left and right to adjust effort. Press Enter to make it your default, or press s to use it for this session only.
WHAT YOU'LL SEE
On Oct 6 we switched a fresh Opus 5.5 session to Sonnet 5 at xhigh effort with s, and the default for new sessions stayed Opus 5.5. Press Escape and the picker keeps what you had.

/permissions

WHAT IT DOES
It shows and edits the three lists every tool call is checked against. Allow skips the prompt, ask always confirms, and deny always refuses.
WHEN TO RUN IT
Run it in your first session in a repo, when you keep approving the same prompt, and the moment you find a gap. You can run it while Claude is responding, and your change applies from Claude's next tool call.
HOW TO RUN IT
Type /permissions, or its alias /allowed-tools. Pick a tab (allow, ask, deny, recent auto mode denials, auto mode rules, or working directories), choose Add a new rule, type it, and choose where it's saved.
WHAT YOU'LL SEE
Every rule by scope, and you can remove any of them from the same dialog. Our Oct 6 run showed 31 allow, 0 ask, 0 deny. We added one deny rule for gh pr merge, saved to user settings.

/clear

WHAT IT DOES
It starts a fresh conversation with an empty context. The old conversation is kept, and you can bring it back with /resume.
WHEN TO RUN IT
Run it when you finish one task and start another, or when Claude keeps returning to something you've moved past. To stay in the same conversation and just free up room, use /compact instead.
HOW TO RUN IT
Type /clear. Add a name to label the old conversation in the /resume picker. /reset and /new do the same thing.
WHAT YOU'LL SEE
On Oct 6 our context fell from 79.2k tokens (8% of the window) to 39.6k (4%). Messages fell from 41.1k tokens to 1.6k. Memory files held at 8.7k, so CLAUDE.md stayed loaded.

/login

WHAT IT DOES
It signs you in and sets who pays: a Claude subscription, an Anthropic Console account billed by API usage, or a third-party platform like Amazon Bedrock.
WHEN TO RUN IT
Run it when you set up a new machine, when you change plans, or when you want to switch between your subscription and API billing.
HOW TO RUN IT
Type /login, pick one of the three options, and sign in. Then type /status to check which one you're on.
WHAT YOU'LL SEE
/status shows your login method. Ours said Claude Pro account: a subscription, not API billing. Press Escape and it says Login interrupted, and your login doesn't change.

/goal

WHAT IT DOES
It gives Claude a finish line. After every turn, a separate small, fast model reads the conversation and says met, not yet, or impossible. Not yet, and Claude starts the next turn on its own.
WHEN TO RUN IT
Run it whenever you'd otherwise type "keep going." A goal lasts for this session only. Pair it with auto mode, or run it headless with claude -p.
HOW TO RUN IT
Type /goal and your condition. A condition that holds up has one end state you can measure, the check that proves it (like the test command exiting 0), and what must not change on the way. Add "or stop after 10 turns" if you want a ceiling.
WHAT TO WATCH
The judge doesn't run anything. It only reads what Claude showed in the chat, so ask for proof Claude has to print. Not /loop (that runs on a timer), and not a Stop hook (that lives in your settings file).
